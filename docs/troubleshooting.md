# 故障排查手册

所有 API 错误响应都是结构化 JSON：

```json
{
  "code": "AUTH_REQUIRED",
  "message": "需要有效的访问令牌",
  "technicalDetails": { "requestId": "……" }
}
```

排查时请始终保留 `requestId`：它与本地服务日志中的请求一一对应，且**不包含**任何令牌、Cookie 或查询参数。任务类错误（读取阶段失败）会出现在任务查询接口 `GET /api/jobs/:id` 响应的 `error` 字段中，格式相同。

---

## HTTP 401 `AUTH_REQUIRED` —— 需要有效的访问令牌

- **现象**：任何 `/api/*` 请求返回 401，提示"需要有效的访问令牌"。
- **原因**：服务配置了 `ACCESS_TOKEN`（非 loopback 监听时为强制项），但请求未携带 `Authorization: Bearer <token>` 头，或令牌与配置不一致。
- **处理**：
  1. 确认服务端环境变量 `ACCESS_TOKEN` 的值（或 Docker `.env` 中的设置）；
  2. 在客户端/界面中填入完全相同的令牌（注意首尾空格与全半角差异）；
  3. 用 curl 验证：`curl -H "Authorization: Bearer <token>" http://127.0.0.1:4319/api/...`；
  4. 若你只在回环地址自用，也可以不设置 `ACCESS_TOKEN`（回环 + 无令牌是默认状态）。

## HTTP 403 `ORIGIN_NOT_ALLOWED` —— 请求来源不被允许

- **现象**：请求（含预检 OPTIONS）返回 403，提示"请求来源不被允许"。
- **原因**：请求的 `Origin` 不在白名单中。白名单按**完整 origin**（协议+主机+端口）精确匹配，拒绝 `*` 与 `null`；非回环监听且未设置 `ALLOWED_ORIGINS` 时，默认白名单为空。
- **处理**：
  1. 确认浏览器地址栏的来源与端口（例如从 `http://192.168.1.10:4320` 访问，Origin 就是完整的三段）；
  2. 把该 origin 加入服务端 `ALLOWED_ORIGINS`（逗号分隔，可多个）：`ALLOWED_ORIGINS=http://192.168.1.10:4320,http://nas.local:4320`；
  3. 或者改为从服务所在主机以 `127.0.0.1` 访问（回环来源自动进入默认白名单）。

## HTTP 404 `JOB_NOT_FOUND` —— 任务不存在或已过期

- **现象**：查询、取消或导出某个任务时返回 404"未找到该任务"；访问不存在的接口返回 404 `NOT_FOUND`。
- **原因**：任务 ID 拼写错误；或任务早已结束并超过保留时长（`JOB_TTL_MS`，默认 15 分钟）被清扫；或本地服务在中途重启（任务只保存在内存中，不持久化）。
- **处理**：重新提交歌单即可；若任务频繁"消失"，检查服务是否被 systemd/Docker 重启，以及 `JOB_TTL_MS` 设置。

## HTTP 409 —— 任务状态冲突（`JOB_TERMINAL` / `JOB_NOT_READY` / `JOB_NOT_EXPORTABLE`）

- **`JOB_TERMINAL`（取消任务时）**：任务已进入 completed/failed/cancelled 等终态，无法再取消。无需处理，属于正常竞态。
- **`JOB_NOT_READY`（导出时）**：任务仍在排队或读取中。等待任务完成后再导出。
- **`JOB_NOT_EXPORTABLE`（导出时）**：任务以失败或取消告终，或任务结果不可用；也包括读取被判定为不完整而失败的情形。查看任务 `error` 字段中的错误码（见下文"任务失败错误码"）后重试。

## HTTP 413 `PAYLOAD_TOO_LARGE` —— 请求体过大

- **现象**：请求返回 413"请求内容超过 1 MiB 限制"。
- **原因**：请求体超过 1 MiB 硬上限。本工具的正常请求（一个歌单链接 + 导出选项）远小于该值。
- **处理**：正常使用中不应出现；若你用脚本直连 API，请缩小请求体。该上限不可调大，这是有意设计。

## HTTP 415 —— 媒体类型或压缩不支持

- **`UNSUPPORTED_MEDIA_TYPE`**：`/api/*` 请求必须使用 `Content-Type: application/json`。
- **`UNSUPPORTED_CONTENT_ENCODING`**：不接受 gzip/br 等压缩的请求体（`Content-Encoding` 只允许 `identity` 或不传）。

## HTTP 422 —— 语义阻止

- **`INCOMPLETE_PLAYLIST`（歌单读取不完整，已阻止导出）**：任务本身已成功结束，但其结果被标记为 `complete=false`（例如分页校验失败、上游总数对不上、或未来版本中用户主动提前停止）。服务**拒绝**把不完整的歌单伪装成完整导出，因此不生成文件。处理：直接重试；若同一歌单稳定复现，请记录歌单规模与 `requestId` 反馈。
- **`UNSUPPORTED_PROVIDER`（当前运行环境不支持该平台）**：请求的平台未在当前运行时注册（例如当前版本仅注册了网易云）。以界面实际提供的平台为准。

## HTTP 429 `QUEUE_FULL` —— 限流或队列已满

- **现象**：提交歌单读取返回 429"任务队列已满，请稍后重试"。
- **原因**：排队任务数已达上限（`MAX_QUEUED_JOBS`，默认 100）。
- **处理**：等待正在运行的任务完成或主动取消，再重新提交；服务同时最多运行 2 个任务（`MAX_CONCURRENT_JOBS`），大批量导入请自行在客户端节流。
- **关于 Retry-After**：API 层面的 429 响应**不携带** `Retry-After` 头（队列瞬时状态，无法给出可靠等待时间）。**上游方向**的 429 由抓取层处理：对网易云返回的 429，抓取层会尊重其 `Retry-After`（无该头时按指数退避，单次等待上限 30 秒）做**最多 3 次**有界重试，重试随时可被用户取消；重试耗尽后任务失败并给出明确错误码，不会无限退避。

## `EGRESS_NOT_ALLOWED` —— 已阻止不安全的上游请求

- **现象**：任务失败，错误码为 `EGRESS_NOT_ALLOWED`。
- **原因**：Provider 发出的上游请求未通过出站白名单：目标不是 `https`、携带用户信息、使用非默认端口，或主机名不在白名单（当前仅允许 `music.163.com`、`y.music.163.com`、`163cn.tv`）；跟随重定向也会触发该错误。
- **处理**：本工具刻意只允许上述域名。若你在受控代理/镜像环境中遇到此错误，请检查网络中间层是否改写了请求目标；**不要**通过修改白名单来访问其他域名——该白名单是 SSRF 防线。

## HTTP 400 —— 请求内容无效

- **`INVALID_PLAYLIST_INPUT`**：粘贴的内容无法识别为歌单链接/ID。请粘贴完整的公开歌单链接（含 `playlist?id=数字`）或纯数字 ID。
- **`INVALID_JSON` / `INVALID_REQUEST`**：请求不是合法 JSON，或字段不符合约定（多见于脚本直连 API）。
- **`INVALID_EXPORT_OPTIONS`**：导出选项组合无效（例如非法的格式或字段取值）。

## 任务失败错误码（出现在任务 `error.code` 中）

| 错误码 | 含义 | 处理建议 |
|---|---|---|
| `PROVIDER_HTTP_ERROR` | 上游返回 4xx/5xx（404 表示歌单不存在） | 确认歌单为公开且 ID 正确；稍后重试 |
| `PROVIDER_SCHEMA_DRIFT` | 平台返回的数据格式发生变化 | 等待工具适配更新 |
| `HTTP_TIMEOUT` | 单次上游请求超过 15 秒 | 检查网络；稍后重试 |
| `NETWORK_ERROR` | 网络请求失败（DNS、连接被拒等） | 检查本机网络与代理设置 |
| `RESPONSE_TOO_LARGE` | 单个上游响应超过 8 MiB 上限 | 属安全保护；若稳定复现请反馈 |
| `INCOMPLETE_PAGINATION` | 分页完整性校验失败（见下节） | 重试；稳定复现请反馈 |

## 服务启动失败

| 报错 | 原因与处理 |
|---|---|
| `ACCESS_TOKEN 在非 loopback 监听时必须配置` | 把 `HOST` 改回回环地址，或设置 `ACCESS_TOKEN` |
| `ACCESS_TOKEN 格式无效` | 令牌为空、含控制字符或超过 4096 字节 |
| `HOST 格式无效` | `HOST` 需为合法 IP 或主机名，不含空白 |
| `ALLOWED_ORIGINS ……` | 白名单必须为逗号分隔的完整 HTTP(S) origin，不含路径、查询或凭证 |

## 关于"歌单超过 1000 首，读取不完整时导出被阻止"

网易云接口按页返回曲目（本工具每页最多 1000 首）。超过 1000 首的歌单会**自动分页读取**，读取过程受多重完整性校验保护：页游标必须前进、页数与条目数有安全预算、累计条目必须与上游声明的总数一致、详情批量接口的结果按原始顺序重排。任何一项校验失败，任务都会以 `INCOMPLETE_PAGINATION` 失败（或结果被标记 `complete=false`），导出随之被阻止（409 / 422）。

这是**有意设计**：宁可明确失败，也不静默截断出一个"看起来完整"的导出文件。遇到时直接重试通常可以恢复；稳定复现请携带歌单规模与 `requestId` 反馈。
